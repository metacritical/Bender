## Procedural material authoring
4. Define a versioned, human-editable material recipe file. Include palette/background/accent colours, brightness, pixel scale, grain density and seed/variation; distinguish block-face layering (grass top/grass-over-dirt sides, dirt, sand), water, and lava. Make a registry of procedural kinds including a Voronoi option and a deterministic fallback for invalid entries. Generate/load the atlas or shader inputs from recipes, not hard-coded atlas constants; changing a recipe must update visible blocks without restarting.
5. Add Object/Play and Edit modes independently of the `~` live Janet console. In Edit mode unlock the cursor, ray-pick a block, open a separate right-side inspector window/panel with material kind, colours, grain and scale controls and preview; explicit Apply to selected type or region plus Save and Reload. Do not silently change every block of a type while merely selecting it. File and UI edits share the same validated schema and converge through the reload path.
6. Add a first-person pickaxe held in view and preserve the existing block editing behavior; compare grass/dirt/sand and water to the supplied screenshots as reference direction (not pixel-exact source assets). Verify functionality and screenshot; commit each bounded feature atomically.
