# Typed/unboxed AOT roadmap: coverage before dispatch

**Design scout, 2026-10-23.** This is a ranking of engineering experiments, not a forecast of achieved throughput. Source references name symbols first; line numbers are approximate because `src/core/vm.c`, `tools/loop-executor.janet`, and `tools/callgraph.janet` are being edited concurrently. The authoritative baseline is [the measured capability audit](typed-path-capability-audit.md), especially §§Q1–Q3 and “Implications.” The later [loop feasibility scout](aot-loop-codegen-feasibility.md) corrects its optimistic interpretation of the 169 loop refusals. This document changes neither the dynamic-first language model nor the no-JIT deployment constraint.

## Target and decision rules

This is a **Lisp-family, dynamic-first, ahead-of-time VM compiler for games**, in the GOAL lineage: infer and widen from untyped code and offline workload-specific PGO; offer *optional* checked hints only where a report demonstrates payoff. Mandatory whole-program static typing is **not** a goal. No JIT or runtime code generation on iOS/Switch; preserve a small approximately 1–2 MB runtime and a working bytecode fallback. The aspiration is IL2CPP/Static-Hermes-class compiled throughput—roughly **2–3× the current native C path** on a comparable hot workload—not automatic Rust parity. Do not confuse GUI FPS with CLI throughput. The interpreter measured **0.032× Rust**, whereas AOT+PGO release measured **0.47–0.48× LuaJIT** on the cited CLI comparison ([audit §Q4](typed-path-capability-audit.md); [PGO plan, “Goal and current evidence”](profile-guided-optimizer-plan.md)).

In one sustained release sample, `run_vm` accounted for **1,383/3,380 stack tops ≈41%** (the rough “42% share”); it includes operations run under the VM and is **not** an independently subtractable dispatch tax (`profile-guided-optimizer-plan.md`, “First measured slice,” approximately lines 71–92). Even completely eliminating this sampled share, impossibly, gives an Amdahl ceiling of about **1/(1−0.42) = 1.72×** on that workload. A more plausible 25–50% reduction *of that share* alone gives **~1.12–1.27×** whole-process improvement; stronger gains require also removing boxed aggregate traffic, allocations, barriers, and formatters outside `run_vm`. These are illustrative bounds, not additive per-item promises, and an AOT-vs-native-C 2–3× aspiration cannot be obtained solely by shaving `run_vm`. Attribute different effects separately and validate comparable release binaries and exact output.

The real-ttfx kernel census is **8 emitted, 783 refused**, including 338 nonzero-param “types not proven” refusals that hints *might* address, 115 nonloop zero-param “types not proven” refusals, and 169 loop-first refusals ([audit, “How much headroom”](typed-path-capability-audit.md)). **These classes are diagnostic ordering, not an independent additive opportunity calculation.** The [loop feasibility scout §6](aot-loop-codegen-feasibility.md) found that **115/169 loop-vetoed definitions ALSO have zero parameters**; lifting only the loop gate leaves at most 54 newly classifiable, before body checks. None of these raw definition counts implies hotness. Existing hints are closed-vocabulary, boundary-checked *panic* contracts, trusted internally, contradicted-body-refusing, Tier-A only; PGO is observational evidence with boxed fallback, **not a reason to make a speculative hint** (`callgraph.janet`: `extract-hints`, `check-hints`, `wrapper-for`, `dispatch-wrapper-for`; [audit §Q1](typed-path-capability-audit.md)). A hint cannot lift the loop veto, constructor poison, zero-arity gate or recursion refusal. Report marginal cost and benefit against the **current continuation-enabled baseline**: native-to-native continuation v1 has effectively zero taken-edge benefit and +0.6–1.0% always-on cost. On decrypt, 79% of refused edges call a non-`JANET_FUNCTION`, another 20% have no `native_code` ([native continuation measured postscript](native-continuation-design.md), approximately lines 1027–1116). Coverage and boxing outrank more call-dispatch work.

**Acceptance standard:** fail-closed compiler diagnostics, exact output versus the boxed path, mixed-width/GC/forced-quantum/exception tests, executor-enabled builds (`make NATIVE_EXECUTORS=1` *and* runtime `JANET_NATIVE_EXECUTORS=1`), two isolated PGO collections and verified release when applicable, same-sitting interleaved A/B and held-out workloads. The established gate is **±3% per effect and ~0.1–0.3% geomean** for otherwise identical builds (`native-continuation-design.md`, measured postscript). A local kernel gain is not a release geomean claim. Record time **inside eligible functions and allocation/exit counts**; a proposed feature with less than ~5% hot share cannot credibly move an individual effect by >3% unless it also changes substantial adjacent work.

## Ordered engineering roadmap

The ranking weighs potential *release workload leverage* against cost and prerequisite risk. Sizes are approximate engineer-weeks including narrow tests/diagnostics, **not** commitments. A zero in an expected-win column means “unproven or below the gate,” not “provably impossible.” A prerequisite correctness item is separated from performance rank.

### 0. Safety and attribution gate — before expanding typed memory

**Today/gap.** `emit-intrinsic-call` emits typed loads/stores from raw pointers, while the production `aot-run-cc` command in `src/boot/boot.janet` lacks `-fno-strict-aliasing`. The mixed-field parity fixtures in `tools/callgraph.janet` (`mkptr` and generated C pointer samples) are `double[8]` rather than typed backing storage. The audit demonstrates an optimized mixed-field divergence and a falsely reassuring parity oracle ([audit, “Two defects found in passing”](typed-path-capability-audit.md), approximately lines 408–435); the actual calloc-backed AOT example did **not** diverge. **Design:** audit effective types/alignment, add `-fno-strict-aliasing` where appropriate or use layout-correct access, use a byte/declared-layout fixture, test mixed numeric fields at -O3/ASan, and expose structured per-PC time, VM exits, allocations and rejection reasons. **Win:** correctness and trustworthy measurement, no claimed speedup; **risk:** low implementation but high latent miscompile severity; **size:** 1–2 weeks. Do not substitute a build flag for pointer bounds/lifetime proofs. The flags and fixtures are future work, not edits made by this scout.

### 1. Split reused physical slots into typed per-PC value lifetimes (highest strategic leverage)

**Today/gap.** `infer/analyze` and `scan-def` propagate hint/PGO/call-site types through physical slots (`tools/infer.janet`, approximately lines 275–420; interfunction fixpoint near 752). `flow-check` already computes CFG block-entry states (`tools/callgraph.janet`, approximately lines 2133–2298), **but** `emit-fn-c` still gathers all writes to each physical slot into `wsets`, chooses one C declaration with `decl-kind`, then refuses incompatible mixes (approximately 2678–2711, 2861–2993). Simply attaching a per-PC type to this existing C variable does *not* solve its declaration collision. The audit’s `radial-fraction` required a source rewrite to reduce named locals: hint alone refused a mixed `s16`, hint plus restructuring yielded one kernel and ~3.5× **on that isolated test** ([audit, “Validated pilot recipe”](typed-path-capability-audit.md), approximately lines 673–699).

**Design.** Build an explicit CFG with reachable predecessor states, def/use and live-range information; version each write as `(pc, slot)` (full SSA with typed phi/copy insertion, or first a conservative split of proven-disjoint live intervals). Propagate types to uses and through join nodes; lower independent versions to separate C temporaries, never reusing a physical slot C declaration for incompatible types. Widen real joins conservatively; keep `:unknown`/nonnumeric and unsigned >2^53 semantics fail-closed. Carry table-shape provenance, call target, exact bytecode PC and source identity alongside each version. Verify loops with interrupt/resume and retyping at merge, avoid excessive phi copies, and migrate *both* inference and emission rather than only `flow-check`.

**Expected win:** potentially converts part of the 338 hint-addressable upper bound **without forcing programmers to rewrite source** and benefits all other typed features; a hot leaf may clear ±3%, but the released 37-effect geomean has **no defensible number until a hotness-weighted counterfactual census**. **Risk:** high—joins, redefinitions, aliases, unsigned arithmetic, table shape and bit parity; **size:** ~4–8 weeks staged. **Gate:** tally actual mixed-slot refusals by source-qualified hotness, trial split-only implementation on `radial-fraction` plus diverse control-flow, require newly emitted parity-clean *hot* kernels and a release A/B. This is #1 by breadth and enabling effect, **not** because 338 would turn into 338 kernels; unsupported body ops and nonnative callees remain.

### 2. Specialized scalar-pair return ABI, then general flat aggregates

**Today/gap.** `infer/analyze` represents `mktup` as opaque `:tuple`; `emit-fn-c`, direct kernel calls, `wrapper-for`, and `emit-native-lib` admit one C value/opaque pointer, not a two-component result (`tools/infer.janet`: `scan-def`; `tools/callgraph.janet`: `emit-fn-c`, `wrapper-for`, `emit-native-lib`, approximately 2678, 4193, 5227). One-TU emission and literal kernel→kernel C calls **already exist** and -O3 may inline them ([audit §Q3b](typed-path-capability-audit.md)); adding interprocedural *representation*, not merely linkage, is the gap. Hot `[col row]` returns from `ctx-path-step`/`ctx-coord-on-line` and the cross-module `E/ease` edge retain boxing ([native continuation design](native-continuation-design.md), approximately lines 643–655; [runtime feedback](ttfx-pgo-runtime-feedback.md), approximately lines 223–231).

**Design.** First recognize a **fixed two-scalar, immutable tuple** with two proved field types, one compatible shape at every return, and known consumers. Generate a stable C pair type and C direct-return ABI in the module, destructure via direct scalar access; materialize a Janet tuple exactly once at a boxed/unknown call, escaping reference, reflection, debugger or public wrapper. Keep dynamic and cross-module calls boxed unless source-qualified identity and compatible declared ABI are proven in the AOT unit; `E/ease` will not become a direct C edge just because its name is known. Test copy/value semantics and different architectures' struct-return calling conventions. Next, generalize the machinery to `table-flat`: `infer/analyze` currently *sticky-opens* a shape on pass/return; `emit-fn-c` emits a function-local stack struct for its one-entry-block `mktab` (`tools/infer.janet`, approximately 167–207; `tools/callgraph.janet`, approximately 3375–3410). Introduce a module-wide structural layout identity, shape-aware param/return/call typing, alias/escape analysis, and boxing at any unknown boundary, rather than merely removing the escape veto. Include `mkstu` only after its own shape rules; `ffi/defstruct` pointers already provide persistent state but do not avoid cross-call `:long` reboxing ([audit §Q2](typed-path-capability-audit.md)).

**Expected win:** pair ABI may clear ±3% on **motion-dominated effects** if the boxed tuple/call subtree is hot, but unknown geomean; generic flat-table crossing has lower marginal payoff until this is measured. **Risk:** medium-high for pairs, high for general escape and ABI/versioning; **size:** ~3–5 weeks pairs + ~5–9 weeks generalized shapes. **Gate:** isolate tuple alloc/box counts and matching hot edges, prove parity and compare motion-effect and 37-effect release times independently. Shared machinery with #1 is helpful, not a logical requirement for a narrow pair-only proof.

### 3. Native string/buffer construction, beginning with a restricted fast path

**Today/gap.** `flow-check` makes `mkstr`/`mkbuf`/`mkstu`/`mktab` destinations `:unknown`, and `emit-fn-c` refuses unsupported construction (`tools/callgraph.janet`, approximately 2222–2227, 3083, 3387). `table-flat` is the exception for a proven local `mktab`. Tier-B `loop-executor` treats general construction as VM boundaries; it already offers a narrow guard/poll/commit buffer-append path (`tools/loop-executor.janet`: boundary-ops and guarded buffer push; `src/core/buffer.c`: `janet_native_buffer_push_string_ready/commit`). The GC API already has `janet_gcshadow_mark/push/pop_to`, and `janet_mark_roots` scans those roots (`src/core/gc.c`, approximately 2344–2381, 3125–3152; `src/include/janet.h`, approximately 2253–2262). `janet_string_begin/end` allocate writable GC-owned bytes then finish/hash; `janet_buffer` and `janet_buffer_extra` can allocate/reallocate and panic (`src/core/string.c`, approximately 33–56; `src/core/buffer.c`, approximately 81–149).

**Design.** Start with a length-proven single-operation string copy/concat or capacity-proven buffer append, **not** arbitrary serializer graphs. Specify byte-length overflow, encoding/immutability, hash finalization, and allocation/panic ordering identical to bytecode. Keep all live Janet objects—including the partially constructed owner and inputs—rooted in fiber slots or scoped shadow roots across every GC-capable call; never retain a buffer-data interior pointer across growth. Use a guard-before-side-effect and poll-before-commit protocol at a Tier-B checkpoint, with the original PC retained on failure, suspension or panic; a Tier-A wrapper without fiber/PC cannot magically become resumable. Route anything not proved to the VM. Add forced-GC, tiny-quantum, panic, alias and byte-parity cases.

**Expected win:** plausible >3% on **formatter/serializer-dominated effects** if attribution shows repeated VM exits and heap construction; pure numeric effects gain ~0. **Risk:** high GC/rooting and exception/resume correctness, possible code-size conflict with 1–2 MB goal; **size:** ~4–7 weeks for the restricted path, considerably more for general constructors. This expands coverage where checked hints cannot help; it does not depend on a region allocator.

### 4. Constant-offset pointer arithmetic and explicitly typed unsafe operations

**Today/gap.** `ffi/defstruct` emits metadata-backed `:kernel {:pread|:pwrite [type offset]}` accessors; `extract-intrinsics` and `emit-intrinsic-call` lower their resolved, non-tail calls to typed C loads/stores with a proved pointer base and constant field offset (`tools/callgraph.janet`, approximately 385–433, 2623–2676). A persistent record works, but `:long` fields and pointer/nested fields are boxed-only (`src/boot/boot.janet`: `ffi/defstruct`, approximately 4777–4866). `unsafe/ptr-add` exists as a C function, *not* an emitter intrinsic; **there is no `unsafe/peek`**, the read operation is `ffi/read`, and bare `ffi/read`/`unsafe/poke` are not lowered (`src/core/ffi.c`: `cfun_ffi_ptr_add`, `cfun_ffi_buffer_read`, `cfun_ffi_poke`, approximately 2115–2132, 2243–2254, 2278–2291; [audit §Q2](typed-path-capability-audit.md)). A generated setter returns the input value; bare `unsafe/poke` returns nil—do not conflate their semantics.

**Design.** Add an **opt-in resolved intrinsic** with known pointer argument, exact signed byte displacement (initially constant), pointer return and no spread/tail surprises; refuse uncertain identity/type/overflow. For indexed entity arrays, a dynamic stride requires an exactly represented signed integer, multiplication/addition overflow checks, a buffer/base ownership contract, and explicit validity of in-allocation offset/one-past—not an unchecked float-to-pointer cast. Bare reads/writes require a separate whitelist of literal FFI storage types, exact offset/alignment/provenance, nil-vs-value return semantics, sandbox/FFI permission parity, and no aliasing UB. Keep existing metadata accessors as the safe starting interface; do **not** globally translate every `unsafe/*` call. Cross-platform layout comes from `ffi/size`/`ffi/align`, never guessed C widths. Unsafe remains explicitly unsafe even when a checked hint guards pointer *type*: it does not prove bounds, lifetime or effective type.

**Expected win:** for a demonstrably hot array-of-structs animation loop, likely >3% **locally** from eliminating accessor calls/boxes; no measured whole-app gain yet, and a Tier-A striding loop remains vetoed. **Risk:** high memory corruption/UB despite modest syntax lowering; **size:** ~1–3 weeks constant offset plus tests, ~4–7 weeks for dynamic stride and guarded raw access. Complete item 0 first and combine with *resumable Tier-B loop fusion*, rather than misusing Tier-A loop output.

### 5. Annotation advisor and source-qualified coverage report

**Today/gap.** `extract-hints`/`check-hints` parse and validate optional closed-vocabulary contracts; `infer/analyze` records `pts`, `rts`, PGO provenance `pprov`, and shape information; `emit-native-lib` prints `native-skip` strings after candidate and body/dependency checks (`tools/callgraph.janet`, approximately 663–809, 1775–1791, 5244–5478; `tools/infer.janet`, approximately 275–402). Strings and unqualified function names cannot establish “hint this and it **will** emit”: slot collisions, loops, constructors and missing callees still refuse. The source-text scan is diagnostic only; compiler-expanded binding identity must remain authoritative.

**Design.** Preserve structured per-definition identity (source file, expanded binding ID, line/site), type evidence per param/return with profile origin and observed conflict, first and *subsequent* refusal reasons, failed body op/PC, slot live-range collisions, callee dependency, shape escapes, and sampled exclusive time/edge counts. Include a `hint-bad` gate and zero-arg/loop structural categories. Rank by hot time × plausible saved boxed work, not 338 definition names. Recommend only the minimal exact `{:hint {:params [...] :returns ...}}` contract **as a candidate**; do not convert a unanimous PGO observation into an asserted user contract. A disposable, non-mutating counterfactual compiler pass with proposed hints can elevate the label to “verified kernel candidate” only if the *entire emitter* and dependencies pass. Generate a portable JSON report plus terse source-located explanations, never rewrite user code automatically.

**Expected win:** indirect, zero runtime speedup by itself; enables opt-in hints where the audit measured **~1.56× for an otherwise refused leaf**, and explains why an already inferred leaf showed no measurable hint win ([audit §Q1 experiments](typed-path-capability-audit.md)). **Risk:** misleading/unsafe advice from stale profiles, duplicate names, or correlated workload-specific evidence; **size:** ~1–2 weeks reason/provenance report, ~3–5 weeks for trustworthy counterfactual+hotness integration. A diagnostic-only first stage can precede #1; versioned-slot information improves later advice.

### 6. Zero-argument kernels (separate cheap eligibility trial)

**Today/gap.** `emit-native-lib` initializes `concrete` with ` (> (length pt) 0)` and excludes varargs, and both PGO alternative tiers also require positive arity; standalone `emit-native-all` repeats that gate (`tools/callgraph.janet`, approximately 5250–5255, 5310, 5354, 3899). The audit counted 115 nonloop zero-param type refusals; the loop scout separately found 115 zero-param definitions inside 169 loop-first refusals. Removing the check **does not make those looping definitions safe**. There is no parameter hint to add; a return hint alone may already be valid, but still must match body inference. A zero-param `void`-argument C kernel and boxed wrapper arity guard look feasible; verify compiler representation for captured environments, bound module globals, constant/pure return, no-arg direct calls, and return boxing.

**Design:** admit only loop-free, non-vararg, concrete-return, noncapturing definitions through existing body/dependency gates; emit `fn(void)`/wrapper with exact argc=0 and preserve identity/registration. Keep loop/reflection/constructor exclusions. **Expected win:** probably **sub-floor** in release unless hot zero-arg leaves repeatedly run from boxed code; 115 is a diagnostic population, not 115 working kernels. **Risk:** low-medium implementation, medium risk of wrong globals/registration semantics; **size:** ~1–2 weeks. Gate by hotness and emitted C/parity before investing in generalized closure/vararg support.

### 7. Build switches: `-O3` runtime, LTO and architecture tuning (cheap, not magic)

**Today/gap.** The AOT linker/compiler uses `-O3 -fwrapv -fno-math-errno -fno-trapping-math` for generated `app.c`/`native.c`, but links a normally `-O2 -g` `libjanet.a` (`src/boot/boot.janet`: `aot-run-cc` invocation, approximately 6472–6478; `Makefile`: `CFLAGS?=-O2 -g`, approximately line 56). No shared LTO across the objects, no default `-march`/`-mcpu`; `--ldflags` can append flags but does not rebuild the archive ([audit, “Compile flags”](typed-path-capability-audit.md)). Keep `-fwrapv` correctness and deterministic math subset; do not blindly use `-ffast-math` or a host CPU flag for distributable iOS/Switch builds.

**Actual disposable experiment.** At pinned `d5a24e5d`, built two `make NATIVE_EXECUTORS=1 -j8` runtimes under `/tmp` with default `-O2 -g` and clean `CFLAGS='-O3 -g'`. Seven alternating runs of a 3-million-iteration Janet numeric loop under `JANET_NATIVE_EXECUTORS=1` and `/usr/bin/time -p` returned identical `171.767348213509`. Raw wall seconds, in run order: O2 `.18,.10,.11,.11,.10,.11,.12`; O3 `.14,.12,.11,.11,.10,.11,.11`; **median .11 versus .11 seconds**. Workload and observations were in `/tmp/janet-roadmap-bench.janet` and `/tmp/janet-roadmap-timings.tsv`; the disposable worktree was removed. This startup-inclusive **interpreter microbenchmark did not confirm executor activation** and lacks centisecond resolution for a small effect; it neither proves nor disproves an AOT gain, and **LTO/architecture flags were not measured**. No 37-effect gate was run.

**Design:** separately rebuild both runtime archive and generated code with compatible LTO tooling, test the platform cross-linkers and artifact sizes; A/B reproducible release binaries with fixed profile and per-target `-mcpu` where legal. **Expected win:** plausible modest single-digit percent at best until measured, and perhaps below ±3% per effect; no claimed gain from this experiment. **Risk:** compiler/platform incompatibility, code-size growth, FP/alias correctness; **size:** ~1–3 days for a proper micro + ~1 week cross-target/size/release gates. Do not rank this above coverage merely because changing a flag is easy.

### 8. Per-frame regions, **deferred until escape and allocation evidence**

**Today/gap.** `janet_smalloc/srealloc/sfree` allocate individual C blocks and track them; they are **not a bump allocator** (`src/core/gc.c`, approximately 3315–3381). The GC’s private slab/nursery is **not** a resettable user/frame region ([audit §Q3a](typed-path-capability-audit.md)). Exposing a bump pointer to emitted C without an ownership model would make native pointers dangle across frame return and Janet heap references invisible to tracing.

**Design:** begin with an explicit per-tick *scratch byte* region containing no Janet references; define owner (fiber/tick), lifetime, nested frame marks, allocation failure/overflow, reset on normal exit and panic, suspension/resumption across ticks, cross-thread/fiber access, and promotion/copy on escape. If regions ever contain Janet values, enumerate roots to minor/major GC, enforce write barriers for intergenerational/cross-owner pointers, and forbid use after reset. Region-backed strings must be copied to GC-owned immutable strings before escape; region memory does **not** root partially constructed GC objects. Compare bounded scratch reuse with existing heap/GC and track peak memory/latency, not just allocations/s. **Expected win:** possibly frame-tail latency on allocation-heavy games, but **no justified steady-state speed prediction** without profiling; likely disappointing if hot cost is boxed lookup or formatter implementation rather than malloc. **Risk:** very high lifetime/GC/interrupt correctness and platform footprint; **size:** ~6–12+ weeks. Defer generic Janet-visible region objects until a restricted scratch prototype beats simpler construction/rooting work.

## Dependency graph and stop rules

```text
structured hotness/exit/allocation + source-qualified refusal reporting (5)
       ├──> choose/verify versioned slot typing (1) ──> better pair/shape proofs (2)
       ├──> choose formatter constructor slice (3)
       └──> choose memory/zero-arg/build trials (4, 6, 7, 8)
correct mixed-layout alias/fixture gate (0) ──> any expansion of typed unsafe memory (4)
paired scalar result (2a) ──> optional generalized cross-function table-flat (2b)
GC shadow roots + effect/PC/quantum protocol ──> native construction (3)
unsafe intrinsic contract (4) + safe Tier-B polling/materialization
       ──> actual native stride across persistent entity arrays
explicit nonescape/owner/reset + GC visibility ──> per-frame region (8)
```

**Loop caveat:** Tier-A kernels replace a bytecode definition and have raw local C variables but **no resumable fiber/PC frame**. `janet_native_trampoline` is a call-edge mechanism; native-to-native continuation does *not* make a raw-C-local backward jump resumable. Tier B already emits safe `janet_native_poll`/`NX_EXIT` loops and one narrow fused unboxed numeric pattern (`loop-executor.janet`: `numeric-sum-pattern?`, `emit-executor`, approximately 145–239 and 577; [loop feasibility scout §§1–6](aot-loop-codegen-feasibility.md)). Generalize **profile-selected Tier-B loop fusion** with liveness-derived materialization and forced-quantum parity rather than simply removing the Tier-A veto. It is a complementary implementation track to #1/#4, *not* 169 instantly freed kernels. The current continuation attempt at every call PC needs profile narrowing or a proven frame-bookkeeping win before default-on expansion ([native continuation postscript](native-continuation-design.md)).

**Most likely to disappoint:** general per-frame arenas (#8) on *throughput*: high design/invariant cost, tempting game-tick analogy, but no proof that bump allocation—not boxed reads, VM exits, barriers or string work—is the dominant release term. The most tempting **false cheap win** is zero-arg admission (#6) or `-O3` (#7): definitions and flags are not time shares, and our `-O3` probe was null within its weak measurement resolution. Even the #1 bet must be retired or demoted if a source-qualified counterfactual finds that mixed slots are cold or body-op refusals dominate after splitting. Seek a reproducible **>3% hot-effect win and >0.3% release geomean improvement**, then measure code size and GC/interrupt parity before promotion.
