# Annotation advisor: evidence-led hints for dynamic-first AOT

**Status:** design scout, not an implemented command or a benchmark result. This specification targets Bender's offline AOT path, **not a JIT**. The default is unannotated source: widening/inference and PGO should make it fast without obliging programmers to type everything. An annotation is a checked ABI contract, not observed type evidence or a harmless speculative specialization. The advisor must recommend one only when its safety, conversion path, workload relevance, and expected value can be explained.

The authoritative baseline is [`typed-path-capability-audit.md`](typed-path-capability-audit.md), especially Q1 and the ttfx pilot. Its historical real ttfx CLI census was **8 emitted kernels / 783 `native-skip` lines**: **169** loop-vetoed, **115** zero-parameter `types not proven`, and **338** (43.2% of 783) with at least one unproven parameter. The remaining **161** are other refusals; do not invent a finer count from this aggregate. The 338 are an **upper bound on first-gate hint candidates, not 338 viable or profitable suggestions**. A subsequent build or different compiler revision can change the census; the report must name its build and collect its own counts rather than present these numbers as perpetual facts. The audit's `radial-fraction` experiment showed that hints alone changed a type refusal into `slot s16 mixes unanalyzable double/unknown/u64ok`; hints *plus fewer named locals* converted 0→1 kernel and reduced isolated runtime from approximately 1.21 s to 0.34 s (approximately 3.5×). A different isolated dynamic-dispatch pilot converted 0→1 with a hint and improved approximately 1.56×. Neither microbenchmark licenses a whole-effect speedup prediction.

## 1. Inputs and their present-day contract

| Signal | Present representation / consumption | What it proves, and what it does not |
|---|---|---|
| Native emitter decisions | `emit-native-lib` builds `lib-skips` and prints **stdout text** `native-skip <id> <name> <reason>`; `emit-native-all` has the same line contract. The `id` is a build-local graph index, not a cross-build key. `native-lib <N> kernels <outdir>` and `hint-bad <id> <reason>` are also text. | Refusal reason for *this* lowering attempt. There is **no structured refusal file**, source location, or reason code today. Logs are diagnostic, not a stable parser API. |
| PGO profile | JDN **data**, a bare array of `[identity info]` rows; `identity = [source-file definition-line definition-name]`, `info :calls` is a nonnegative integer, with `:params`, `:rets`, `:signatures`, `:edges`, `:calledges`, `:from`, and `:type-from` where present. `profile-rows` validates and `profile-index` matches verified source/line/name before inference. | Per-observed-definition *frequency and type/edge evidence*, not wall time, not guaranteed whole-program coverage, and not a permission to turn a sampled type into a checked contract. A function with zero observations is **unmeasured**, not proved cold. |
| Runtime native telemetry | Generated `executor-stats(id)` tuple `[entries, edges, fallbacks, ops, vmexits, continuations]` (indices 0–5) for emitted Tier-B executors; `executor-global-stats()` contains attachment and VM-exit/continuation totals; `executor-exit-stat(opcode)` reads the VM-exit opcode histogram. Do not silently attach an executor's counters to a namesake refusal or interpret an `ops` count as elapsed time. Numeric per-definition stats can be queried at runtime, but no automatic persisted, workload-tagged per-definition telemetry snapshot is part of the refusal report today. |
| Auto-PGO provenance | Raw `<key>.jdn` and sidecar `.run-*.jdn` have companion `<profile>.workload` JDN dictionaries containing `:args`, `:argv`, `:has-stdin`, `:stdin-bytes`, `:replayable`, `:reason`, `:binary`, `:image-bytes`, `:stdout-hash`, `:stdout-bytes`; `--pgo-auto` groups by argv+stdin, merges and parity-gates per workload, and publishes a verified v3 `.meta` cache with `:sources`, `:aggregate`, and individual `:workloads` records (`:profile`, `:oracle`, replay inputs). | Machine-readable replay and grouping, *not* an effect label or per-definition duration. `:stdout-hash` and `:image-bytes` are provenance, **not** the parity authority. Non-replayable or stale runs must not yield a confident recommendation. |

Emission sites and current **verbatim reason forms** (spacing and `?` matter): `describe-types-lib` prints `params [<space-separated type names or ?>] ret <type or ?>`; the candidate gate emits `types not proven: params [? ? ? ? ? ?] ret double` for the audited six-parameter `radial-fraction` case. Thus a complete line has the form `native-skip 1 radial-fraction types not proven: params [? ? ? ? ? ?] ret double` (the numeric id is only illustrative). Other actual forms include `native-skip 1 hloop loop requires resumable VM quantum polls`, `native-skip 3 c2 ret slot is double not i16`, and `native-skip 1 radial-fraction slot s16 mixes unanalyzable double/unknown/u64ok` (these ids and examples come from **different** audit experiments). `emit-fn-c` also forms `slot s<N> mixes u64 with non-u64: <types>` and `slot s<N> mixes <types>`, with `/`-joined kinds; the emitted `<reason>` can instead be `call to non-native or type mismatch`, `len of non-array`, `unhandled op lds`, `duplicate registration of site, canonical def <id>`, or a failed dispatch branch. The log's `native-skip` line has **no `file:line`**, parameter vector is embedded in prose, and no instruction/PC is supplied for a slot-mixing write. `hint-bad` is a separate invalid-hint diagnostic, never evidence that a hint successfully emitted.

## 2. Identity, eligibility, and ranking

First join **each refusal to exactly one profile identity** using canonicalized source path, definition start line, name, arity/vararg shape, and a build/source digest. The existing `def-site-key` pairs `(source, name, sourcemap first line)` across analysis and real-import registration; `profile-index` already refuses duplicate-name, source/line-mismatched profile rows for inference. Reuse its strict source-resolution rules, but introduce an explicit stable site key rather than persist graph `id` or match name alone. Source edit, generated thunk, repeated same-line definition, ambiguous import, changed arity, absent sourcemap, or divergent workload identities ⇒ `join_status: "ambiguous"` or `"stale"`, **no actionable hint**. Retain `graph_id` only as diagnostic local context. Group observations by replayable **workload**, not by blindly unioning type sets or summing duplicate sidecar runs; show effect/args/input hash and count of independent runs. Distinct effect inputs may exercise disjoint branches. A call count across workloads has meaning only with a documented user-selected workload weight or a canonical ttfx suite weighting; default to separate workload rankings and report overlap, never invent equal production traffic.

For eligible site `f`, workload `w`, proposed action `a`, define

```
Opportunity(f,w) = Calls(f,w) × AvoidableCostPerCall(f,w)       [time]
Score(f,a) = Σw Weight(w) × Opportunity(f,w) × P(convert-to-useful-kernel | reason,action,evidence)
```

`Calls` is `:calls` from that workload's gated training profile, never a compile-log count. `AvoidableCostPerCall` must be an interval derived from **paired calibration** (boxed-vs-emitted microbenchmark at comparable signature/call shape, or instrumented timings added in a future training run); edges, `nx_*` exits/fallbacks/ops, and opcode counters only identify work to calibrate. They are **not time** and must not be added to call counts as though commensurate. Clamp estimated avoidable time to measured workload time; include dispatch/ABI guard cost, altered inlining, changed Tier-B bindings, and a possible regression in the interval. `P` starts as **unknown**, not 1: calibrate by reason/action stratum on held-out top-N attempts, count both conversion and actual useful speedup, and publish denominator and interval. Until enough calibration exists, rank within a clearly labeled **exploration/proxy** lane by verified calls × calibrated-cost *range*, with confidence `low` and `expected_payoff: null` if no timing calibration. For a calibrated lane show conservative low/high score bounds as well as midpoint; avoid ordering overlapping intervals as if precise. Report hypothetical performance estimates as bounds, not a speedup guarantee.

A cold, **observed** refusal with calls below the chosen coverage threshold and whose maximum plausible saving remains below the measured gate's noise floor goes to `not-worth-it`; a zero-call row from an incomplete/truncated training suite remains `unmeasured` instead. No number of static refusals compensates for zero runtime exposure. Preserve the top non-actionable *hot* blockers in a separate “compiler limits” section so the user does not mistake silence for optimization opportunity. If PGO has already produced a working dispatch specialization, estimate only incremental benefit over that **actual** baseline, not a fictional fully boxed baseline. Require a boundary-contract review for every suggested hint: type histogram, signature coverage, arguments from outside the training workload, and possible ABI panic. Incomplete observed type sets cannot prove global safety.

## 3. Actionability is a staged decision, not a regex on the first skip

1. **Hint candidate (`hint-only` only after probing):** at least one parameter, non-vararg, loop-free, unambiguous matching site; `types not proven` with missing numeric/allowed ABI parameter or return type; complete observations support a specific closed-vocabulary hint. Emit the exact proposed form, e.g. `(defn f {:hint {:params [:double :double] :returns :double}} [x y] ...)`, marking each inferred/PGO-backed type and its coverage. `:long`, narrow integer widths, `:double`, `:float`, `:number`, and supported opaque ABI types are legal; a user type such as `:ctx` is **not**. Hints are checked by a panicking wrapper and trusted unboxed internally, while contradiction with inferred body type refuses emission; PGO widening and fallback are separate. **Dry-run the proposal in a disposable copy**: `hint-bad` or another `native-skip` demotes it, even if the first diagnostic disappeared. Never recommend hints on an already emitted kernel merely because another type spelling is possible; the audit's inferred `blend` example saw no measurable benefit.
2. **Reshape-only or hint+reshape:** after a hint probe, another lowering reason remains. Specifically `slot s16 mixes unanalyzable double/unknown/u64ok` is a **whole-register-slot** join, not an SSA value type: collect each write to slot 16 with bytecode PC, opcode, inferred kind and source span, including `ldi` of an int literal, loading the `math/sqrt` cfunction constant, and a double-valued arithmetic write. The existing `emit-fn-c` write sets (`written` / `wsets` and `decl-kind`) know the kinds but discard individual write origins in the printable reason. Only after origin collection verifies distinct source lifetimes may advice say: **“This slot is reused for an int literal, a cfunction constant, and a double; split/inline these named locals to reduce slot pressure, then recompile.”** Do not call a slot itself a source local or claim the proposed source edit deterministically changes allocation. Constructor-produced `:unknown` from `mkstr`/`mkbuf`/`mkstu`/`mktab` must not be mislabeled an ordinary numeric hint opportunity; restructuring might remove a constructor/escape but is not guaranteed. A generic bad op or non-native callee gets a concrete operator/dependency and source-span explanation *only if* lowerable in a verified probe; otherwise `requires-compiler-work`/`unknown`, not “add hint.”
3. **Hard compiler limit:** any backward/self jump under the hybrid wrapper (`loop requires resumable VM quantum polls`); zero parameters or varargs under Tier-A gate; recursive/native dependency cycle, including the audited `fib` `unhandled op lds`; a duplicate registration, unsupported lowering, or a constructor kind with no legal representation **when a local reshape does not remove the obstruction**. Explain whether the next step is compiler support, a separately tested algorithmic rewrite, or accepting boxed/Tier-B execution. A hint does **not** override any of these. Tier-B whole-frame executors are independent of hints. Do not assume the historical prose that *all native continuation* is absent applies to current Tier-B: loop Tier-A veto and PGO-selected continuation edges are different mechanisms.
4. **Not worth it / insufficient evidence:** verified cold/low upper-bound benefit ⇒ `cold`; missing, stale, ambiguous, or non-replayable profile ⇒ `unmeasured` (not `cold`); uncertain param coverage or mixed signatures ⇒ `contract-risk`, no exact hint until a person resolves the API and train/test workloads. Hot hard limits remain visible with `payoff: null` and `hint: null`.

An advisory record stores **all stages** (`initial_refusal`, optional `after_hint_probe`, optional `after_reshape_probe`) and final class. A six-unknown-param function can legitimately move from “hint-addressable first gate” to “hint+reshape” or “blocked”; do not count it as an achieved conversion until its kernel appears and both parity and timing pass.

## 5. User surface and lifecycle

Add `--advise[=text|json]` on **non-release `bender --aot ... --native`** rather than a standalone parser of stdout. A normal training AOT build records the structured refusal census alongside its source/profile key, and gathers workload evidence from explicitly replayable `--pgo` runs or auto-PGO sidecars; `--pgo-auto` gates the per-workload merge, then an advice pass reads the verified records and writes a requested report (stdout table or deterministic JSON path). Exact CLI combination/syntax is an implementation choice; forbid `--advise` with `--release` and do not turn on tracing in release. If evidence is absent, emit a census and “collect/replay workload” instructions, **not** a hotness ranking. An optional `--advise-probe` uses an isolated disposable build and recompiles a proposed hint to see the next emitter decision; it never changes checked-in source. No automatic source rewriting, no guess at user-defined types, no deployment of a hinted binary without explicit acceptance, no change in runtime semantics as a side effect of advice. The training binary may expose telemetry through an opt-in small runtime collector that snapshots executor IDs/counters at workload boundaries with build/site identity; release remains built with `-DJANET_NO_PGO -DJANET_NATIVE_TELEMETRY=0` and consumes gated PGO evidence only. Because auto-PGO's cache is keyed by **output basename**, retain that key across training, `--pgo-auto`, advice and release; show a warning on mismatch. Do not describe an advice report as parity-gated merely because the source has a `.workload` sidecar: require verified v3 evidence and a nonempty oracle test where meaningful.

## 6. Minimum compiler/tool work (relative size and dependencies)

| Work | Size | Acceptance criterion |
|---|---|---|
| Structured refusal model in `emit-native-lib`/`emit-native-all`, `emit-fn-c` | **M–L** | Every emitted `native-skip` is also a record with `stage`, stable `reason_code`, original text, typed params/return, op/slot/kinds if applicable, dependency/loop/duplicate target and selected tier; one final status per site including emitted, dispatched or duplicate. Preserve existing stdout for compatibility. Enumerate reasons rather than regex them; account for multi-round dependency resolution and failed dispatch branches. |
| Stable identity and attribution | **M** | Canonical source path + definition start span + name + arity/vararg + source digest; explicit ambiguity on same-name/same-line, generated thunks or missing map. Map slot write PCs to provenance spans and operand kinds where possible; never claim precision beyond source maps. Compare to PGO `[file line name]` under existing `profile-source-matches?` rules. |
| Persist joined census adjacent to profile | **M** | Versioned JDN or JSON file, atomically published with the relevant build/profile generation; links workload IDs, source/compiler digests, `graph_id` (debug only), typed refusals and probes, with freshness checks. A build with no profile still writes a static census, clearly `unranked`. Do not contaminate the bare `.jdn` row-array format that `profile-merge.janet` reads. |
| Runtime per-definition snapshot + workload join | **M** | Optional training-only collector maps executor manifest IDs and available counters to the verified definition identity/workload; records absent counters as absent; reset/delta at workload boundaries, never combine unrelated process lifetime totals. Cross-check attachment verdict and no double counting of calledges, entries or VM exits. |
| Advisor engine/report/CLI | **M–L** | Conservative eligibility/probe pipeline, workload-isolated cost calibration and confidence model, ordered text and same-data JSON, negative-case tests and explicit unknown/stale/blocked categories; defaults leave dynamic-first behavior unchanged. |

Dependencies: identity and structured decisions precede scoring; persistence and workload gating precede confident hotness; timing calibration and top-N conversion results precede numeric payoff. The profile parser already enforces row format and `:calls`; existing PGO inference identity checks and sidecar merging are a starting point, **not** a machine-readable emitter API. Budget above is relative (S = localized change, M = several linked components, L = cross-emitter/toolchain work), not an estimate in calendar days.

## 7. Adversarial validation and ship bar

1. Freeze compiler commit/digest, ttfx source, output-basename key, PGO profile/workload IDs, seeds, input hashes, canonical option coverage, platform/flags and native executor set. Collect and replay representative effects separately; hold out different seeds/effects/signature shapes for contract safety. Do not infer a global type contract from one `decrypt` run. Establish same-source rebuild A/A distribution first.
2. Generate advisor rankings for all 783-style refusals but **sample-check the whole census** for false category assignments; select top-N **actionable hot** sites plus random hot and cold controls. Pre-register N, weights, targeted effects, minimum meaningful gain, and conversion/safety thresholds before source changes. Apply **one suggestion at a time in experimental branches** with explicit human review, preserving original dynamic-first code as baseline; observe `hint-bad`, next refusal, native emitted/dispatch/executor statuses and generated C. Measure `first-gate removed`, `actual kernel conversion`, and `conversion-with-positive-time-gain` separately; report counts and denominators per reason/action, not only successful examples.
3. Gate each variant using committed `/Users/pankajdoharey/Development/Projects/ML/ttfx/bench/validate-bender.py` and [`bench/bender-37-gate.md`](/Users/pankajdoharey/Development/Projects/ML/ttfx/bench/bender-37-gate.md): full **37 effects / 436 canonical option sets**, paired candidate–baseline byte digests over bounded frames, explicit BLOCKED/VACUOUS accounting, optional Rust leg interpreted with its existing port divergences, and Tier-B binding comparison. The equalized gate recorded **368/368 runnable Bender cases exact**, **67 BLOCKED** and one VACUOUS excluded; equalized builds both bound **79/81** executors (`int-string?`, `to-i` refused). A one-sided failure, newly lost executor, ABI-guard panic, or parity drift fails the candidate, even if a microbench speeds up. Use `--candidate`, `--baseline`, `--rust`, `--timing`, `--timing-rounds`, `--json` flags as defined by that harness, not the nonexistent historical `bench-cli-packed-path-vs-rust.py`.
4. Interleave repeated A/B timing rounds, rebuild both variants identically, compare per-effect paired **log ratios** and whole-suite geomean with uncertainty, and compare measured change to the frozen counterfactual predicted interval. The equalized four-round A/A geomean was **0.9992**; approximate **±3% per-effect and ~0.1–0.3% geomean** are practical noise warnings, not a guaranteed statistical CI. Demand an effect beyond a repeated-build empirical noise bound and no meaningful regressions elsewhere; otherwise mark payoff inconclusive, not achieved. A loop-free leaf speedup is not automatically an effect speedup.
5. Report realized-vs-predicted interval coverage, signed error, conversion and positive-payoff precision@N, false hint-only advice rate, contract failures and cold controls. If `radial-fraction`-style slot collisions dominate, downgrade the hint-only prior and surface reshape/compiler work; if top-N does not beat random hot controls after accounting for measurement noise, **do not ship numeric ranking**. Failure-safe release remains the unannotated AOT path and gated PGO; the advisor should make fewer, auditable recommendations, not 338 confident guesses.

Historical audit citations are evidence of feasibility and traps, not validation of a new advisor. No experimental worktree or new build is needed to state this design; actual `--advise` validation begins only after the compiler emits structured records and training captures are joined without ambiguity.
