# Development PGO and size-focused release builds
1. Inspect the current interpreter, AOT launcher, native wrapper/emitter, PGO cache/gate, linker flags, tests, and platform constraints; preserve concurrent working-tree changes. Establish measurable baseline binary sizes and collector coverage.
2. Design a fail-closed profile contract across interpreter, plain AOT, and AOT-native development runs, distinguishing diagnostic evidence from replayable/gateable runs. Implement default development collection with explicit runtime opt-out and sampled native boundary/guard/fallback counters where the current wrappers expose those transitions; never infer an unsupported internal type switch.
3. Add `--release` as a verified AOT-native build mode that freezes eligible evidence, requires a replayable parity workload, and compiles out automatic collection/instrumentation. Define behavior for absent/stale evidence and unsupported options clearly.
4. Add `-Oz` for size-oriented C compiler/linker settings and debug-symbol removal, with platform/toolchain capability checks and retained runtime behavior. Add opt-in `--upx` as a separate post-link packaging stage: discover executable, reject unsupported formats, package a temporary candidate, verify execution/parity, then atomically install it; never silently ship an unverified packed binary.
5. Add targeted and integration tests for default collection, native counters, release opt-out, parity failure, size measurements, strip behavior, UPX available/unavailable paths and packaging failures; run affected suites and commit each verified concern atomically. Document limitations and leave unresolved phases pending rather than claiming completion.
