# TrineXraft Task 1: stale zero-region premise and indexed-access no-go

**HEADLINE — the task brief's central "Tier B matched ZERO regions" premise is falsified on the current workload/build.** The executor-enabled AOT build emits **12 Tier-B executors**, has **412 `janet_native_poll` references** in generated C, and *executes* two definitions: `generate-into` (2,207,658 entries / 54,645,174 native ops) and `fbm-signed-2d` (305,300 / 5,576,851). These retire **60,222,025 native ops**, alongside **726,509,338 interpreted dispatches**. The numeric ratio `native_ops / (native_ops + interpreted_dispatches) = 7.65%` (about 7.7%) is a **mixed-unit work-volume ratio, not native occupancy, dispatch share, or time share**: native ops and interpreter dispatches have different costs. The real Task 1 question is how much *additional* indexed-access work can move into those already-live regions, not how to make the first region appear. The historical zero-region report may reflect another build/configuration, including the documented plain-`make` inert-tier trap, but its cause was **not established**; do not present that plausible explanation as fact.

**Revised decision: NO-GO for this isolated Tier-B change.** A reversible implementation eliminated 2,162,688 native-to-VM exits in the existing TrineXraft benchmark, but five alternating, uninstrumented baseline/candidate runs observed only a **5.4% reduction in worldgen/chunk p50** and **0.6% in mesh-chunk p50**. Neither demonstrates the required double-digit loop-time opportunity on this noisy host. The implementation and fixture changes were reverted; no buffer-access lowering is shipped. The TrineXraft fallback is **parallel meshing across lanes**, not lifting Tier A's settled loop veto or expanding into Tasks 2–3.

Checked branch `ttfx-mixed-regions` at `2eb1d5b0`; the existing `build/bender` was built with `NATIVE_EXECUTORS=1`, its `janet_native_register` contains the real verifier, and a SHA256-identical safety copy is in ignored `tmp/bender-task1-known-good` (`d03f28353d3884e03c97088e2753439189b69b4af2995f070b66b96d2d0374e5`). Compiled `/Users/pankajdoharey/Development/Projects/ML/trinecraft/bench/kernels.janet` with `JANET_NATIVE_EXECUTORS=1 ... --aot ... --native`; ran both sides with `JANET_NO_PROFILE=1` **inline**. No TrineXraft source was modified.

**The apparent native-vs-interpreted slowdown here is unresolved, not an executor regression diagnosis.** The interpreted invocation uses `build/bender`, whereas the native AOT invocation uses the separately linked `build/b-task1-baseline`; these differ in executable code and layout. In response, the *same* native binary was run with `JANET_NATIVE_EXECUTORS=1` and with that environment variable unset, with `JANET_NO_PROFILE=1` inline on both. Both ran the executors: ON had `generate-into` 2,207,658 entries / 54,645,172 ops and `fbm-signed-2d` 305,310 / 5,576,861; unset had 2,207,661 / 54,645,177 and 305,303 / 5,576,854 respectively. Both reported **2,500,740 VM exits and 2,230,404 generated boundary exits**. The handful of entry/op differences also occur on identical repeated runs of this clock-measuring benchmark. Three alternating ON/unset runs produced worldgen p50s ON [5.775, 5.760, 5.947] / unset [5.787, 5.829, 6.233] ms, and mesh ON [6.346, 6.306, 6.522] / unset [6.360, 6.361, 7.991] ms; since both sides execute Tier B, these are an **A/A native control**, not executor ON/OFF effects. Source confirms `JANET_NATIVE_EXECUTORS` gates compiled code (`src/core/bytecode.c:2334-2422`, `src/core/vm.c:3638-3643`) but is not read as a runtime toggle. The available `JANET_NATIVE_NO_CONTINUATION` toggles only native-to-native chaining (`src/core/vm.c:3644-3646`), not Tier B execution. No existing runtime executor OFF switch was found. A genuine same-binary executor causal comparison therefore **cannot be made with this build** without implementing a new switch, which is outside this measurement-only follow-up. Do not infer that executors explain the cross-binary slowdown or that they are harmless; both remain unproved.

The native baseline generated **0 `native-names.txt` lines, 12 `native-executors.txt` lines, 0 `native-continuations.txt` lines, 161 `native-skip` lines**, and 412 occurrences of `janet_native_poll` in `native.c`. The older task brief's 0/0/0 claim is contradicted by this **actual emitted manifest and live runtime activity**; the current Tier B does match and run TrineXraft regions. Positive liveness is established by *executed* per-definition counters: `generate-into` 2,207,658 entries / 54,645,174 native ops, and `fbm-signed-2d` 305,300 / 5,576,851. Merely printing `available 12` would not prove attachment. The benchmark's `mesh-chunk` descriptor was emitted but did not appear among active native-op rows.

The baseline `--work-profile` vector was 726,509,338 interpreted dispatches, 60,222,025 native ops, 2,500,740 VM exits and 2,230,404 generated native boundary exits. The worldgen descriptor alone recorded **2,162,820 boundary exits = 132 × (16,384 voxel stores + one other exit)**: the benchmark generates 120 timed chunks, 3 warmup chunks and 9 world chunks for meshing. The generated `nx_21` exits at its original buffer `put` PC 69 on each voxel and polls at the backedge PC 71. Thus buffer `put` represents approximately **2,162,688 / 2,230,404 = 97.0% of native boundary exits**, not 97% of dispatches or time. Its **2,162,688 executed writes** across 132 generated chunks are a direct dynamic count for this worldgen PC. Because each exit executes that still-unexecuted `put` once in the VM, these writes are a known **0.298% subset of the 726,509,338 interpreted dispatches**—not 0.298% of time or the complete get/put dispatch fraction. Mesher read/write sites and other interpreted indexed accesses have no per-opcode dynamic counter; their executed share of all dispatches remains unknown. A candidate's measured −2,162,495 interpreted dispatches is an *incremental change* to total work, not an opcode-by-opcode baseline histogram.

Static bytecode audit: `generate-into`'s inner voxel loop, PCs 25–71, has **47 opcodes**, including **one `put` (2.13%)**, zero `get` and zero calls. That store executes exactly 16,384 times per generated chunk. The mesher's source-mapped loop regions span 382 static opcodes with 21 `get` and 5 `put` sites (26/382 = 6.81%); these paths are conditional, not 26 operations per iteration. The source includes block and neighbour reads, colour writes and FFI calls (`src/mesher.janet:143-229`). Neither source-site density nor exit density is a CPU-time share. The existing `--work-profile` has no per-opcode interpreted histogram and PGO records receiver types/branches, not per-`get`/`put` time; the requested dynamic collection share of **interpreted dispatches remains unknown**. An isolated `sample` trace was too coarse to attribute the inline `run_vm` cost of a single opcode; direct `janet_put` leaf samples omit dispatcher and re-entry cost. This uncertainty made the pre-edit gate provisional rather than a dishonest numeric time claim.

## Reversible treatment and measured result

The test-only implementation added a register-key buffer `get` with Janet's nil-on-invalid semantics; a `janet_native_buffer_put_fast` accepting only existing nonnegative integer indices and integer values; and a `put` useful-region run-length adjustment. The buffer data pointer was derived from the live object for **each** read/write; growth, invalid indices and values exited *before* mutation at the original PC, letting boxed `JOP_PUT` own reallocation, zero-fill and errors. No pointer survived a call, poll or VM exit. Generic loop state remained in fiber slots, with the existing backward-edge polling and original-PC interrupt handling; no new raw-C-local fused loop or slot-materialisation scheme was introduced. Existing `make test-executors` already exercises forced quantum budgets 1/2 (`test/suite-native-executor.sh:129-134`). A temporary fixture covered buffer/array read/write and guard cases, then was removed with the experiment.

|---|---:|---:|---:|
| Interpreted dispatches, one counter run | 726,509,338 | 724,346,843 | −2,162,495 (**−0.30%**) |
| Native ops | 60,222,025 | 60,222,029 | approximately invariant |
| Native entries | 2,512,958 | 350,274 | −2,162,684 |
| VM exits | 2,500,740 | 338,052 | −2,162,688 (**−86.5%**) |
| Generated boundary exits | 2,230,404 | 67,716 | −2,162,688 (**−97.0%**) |
| `generate-into` entries / exits | 2,207,658 / 2,162,820 | 44,970 / 132 | each −2,162,688 |

These counters measure *work*, not elapsed time; do not add native ops to VM dispatches as if they were equivalent. Counter runs of this timed benchmark are not perfectly repeatable: an identical-image repeat differed by 175 interpreted dispatches, six native entries/ops and ten interpreted calls, while boundary exits stayed exact. The changing `os/clock`/GC path and setup make that small residual a limit on exact vector equality; the 2.16-million-exit effect dwarfs it.

Worldgen paired latency reductions ranged 3.88–7.87%; mesher −0.35–2.63%. The one-off unpaired comparison 6.084→5.416 ms suggested 11.0%, but failed the alternating-pair check and is **not** the conclusion. The host's prior identical-binary A/A comparisons have swung 0.71–1.15 per effect; this modest p50 movement is not a defensible speedup claim. Even granting its observed direction, it misses the explicit double-digit threshold. The mesher's dominant FFI writes and other boundaries remain untouched.

Validation of the reversible treatment: `make NATIVE_EXECUTORS=1` built; generated `nx_21` contained in-loop polls and `janet_native_buffer_put_fast`; emitted executor manifest had 12 lines; live per-definition counters above were nonzero. `make test-executors` passed its budget-1, budget-2, portable, disabled and sanitizer matrix, including 47 identical parked-PC/slot interrupt checks. `./run.sh test` passed all twelve TrineXraft suites. `suite-callgraph.janet` passed 256/256; `suite-aot-*.janet`, `suite-native-array-result.janet`, and `suite-dce-*.janet` passed when run **without** globally exporting `JANET_NO_PROFILE` (the profile-environment test requires profiling). Full executor-mode `make test` also passed (`tmp/task1-native-make-test.log`; `suite-shared` skipped because `JANET_SHARED_STACKS` was unset). The plain-build-mode suite and an isolated byte-identical output comparison were not run; the experiment was reverted and is **not** accepted as a feature. Do not treat those as passed checks. The non-double-digit outcome, rather than unproven correctness, is the reason to stop.
